# 7. Name the project kitbag

- Status: Accepted
- Date: 2026-10-24

## Context and Problem Statement

The working name `agent-sync` overlaps with an existing project in the same
problem space. A public tool needs a concise, memorable identity that describes
carrying a user's configuration between machines without being tied to one agent.

## Decision Drivers

- A short command that is practical to type.
- A metaphor for carrying a user's kit between machines.
- A distinct identity from the closely related agentsync project.

## Considered Options

- kitbag.
- Keep agent-sync / agentsync.
- haversack, fieldkit, agentbag, or muster.

## Decision Outcome

Use `kitbag` as the project and binary name, with the repository
`TomaszJanusz/kitbag` and planned public site `kitbag.sh`. A kitbag carries a
person's equipment; the tool carries their agent configuration to each machine.
The maintainer accepted this name on 2026-10-24.

Reject agent-sync because of the existing closely related agentsync project.
The shortlist also included the longer `haversack`, `fieldkit` with an
existing GitHub organization, the more descriptive `agentbag`, and `muster` with
a looser metaphor. The planning review noted a small existing thematic use of “kitbag” and
accepted that tradeoff; this record makes no claim of exclusive ownership or
current availability across registries and domains.

### Consequences

- Public documentation and commands use `kitbag` consistently.
- `agent-sync` remains historical context, not an alternative product name.
- A name decision does not imply domain registration or package publication.
